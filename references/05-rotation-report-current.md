## 一、核心结论

只能写一个高信息密度段落。先看宏观环境，再概括真正的轮动；不得拆成多段，也不得与第二、第三部分重复。

- 市场当天/当周有没有真实热点；
- 是否处于重大宏观事件前等待期；
- 最强轮入、最强轮出、次级方向；
- 大盘/小盘、成长/价值、周期/防御、硬件/软件、高久期/低久期是否有真实切换；
- 哪些是板块信号，哪些只是公司级或样本噪声。
- 最重要的行情性质变化或维持。

不提前写持续性评级，不写重复总结。

### 选取规则

1. 分别计算每个方向在 All Stocks、S&P 500、Dow Jones 30、Nasdaq 100、Russell 2000、Themes 中进入涨3或跌3的频率。
2. 名称相近、底层成分高度交叉且经济敞口实质相同的方向先合并；仅共享宏观叙事不能合并。
3. 按频率从高到低，结合代表ETF、跨范围宽度、权重股、准确相对收益和可得真实基金流量复核，严格选出轮入3项和轮出3项。
4. 频率相同时，依次以独立范围印证数、宽度、代表ETF与权重股同步性、信号代表性决定排序。

## 三、驱动因素、盈利预期和持续性

只分析第二节最终筛出的三项轮入和三项轮出，不把其余涨3/跌3后台项目重新展开，也不加入其他方向。每个不同板块或主题都单独设小标题并获得与重要性匹配的解释；样本结构或单一公司扭曲的入选方向可以简写，但不能跳过。

只有名称、底层成分和盈利来源均高度重合的方向可合并，例如能源与能源商品。半导体、工业、清洁能源等不同板块必须分别分析，不能因同受AI资本开支、电力需求或宏观因素影响而合并。

每个方向依次写：

1. 直接触发；
2. 产业和宏观背景；
3. 最新财报、指引、订单、利润率、资本开支、信用、商品价格等对盈利预期的影响；
4. 持续性权限只按 ledger 的 `base_state` 判断：`base_state` 为上涨趋势或下跌趋势时，才增加“趋势继续成立需要的条件 / 破坏条件”。

`base_state` 为大型震荡、头部、底部时，到第3项结束，不再加持续性内容。兼容且有效的作者原样状态 `author_exact_state` 只负责正式展示，不自行改变持续性权限。

如果没有同日/同周直接催化，直接写清产业、宏观、权重或样本结构的具体解释；不需要把检索过程或“暂未找到”这类后台核验口径写进正式轮动报告。

## 四、行情性质

本节严格读取 `references/15-fixed-section-four-etf-pool.md`，先按指定顺序完整写出24个固定行业行，再处理允许的追加行业。固定三列，不得增加、删除或改名：

| 板块/ETF | 当天表现 | 行情性质及说明 |
|---|---|---|

单ETF行业只分析指定ETF。半导体、软件、通信服务、可选消费、房地产/REIT五个双ETF行业每天同时取得两只ETF的正常交易时段表现；同向时并列报告，方向不同或幅度明显分化时明确解释权重结构与等权、修正等权或市场宽度差异。不得只用XSD概括半导体；SOXX上涨而XSD下跌时，应写明大型权重半导体强于中小型和宽度。能源与金融各占一行，各ETF行情性质可以不同，按固定顺序依次说明，不能强行统一或拆行。

AI可创建或修改的 `base_state` 合法标签只有：上涨趋势、下跌趋势、大型震荡、头部、底部。`state` 是 `base_state` 的向后兼容别名，二者必须一致。

`AUTHOR_EXACT_STATE` 只有同时满足以下三项才可在第四部分原样展示：`author_exact_state` 非空、`author_exact_active: true`、当前 `base_state` 等于 `author_exact_base_state`。它不是AI创造的第六种基础分类。AI不得自行创建、改写、降级或清除作者原话。

状态必须先继承上一期，再判断是否满足变更条件。没有作者新判断且没有足以破坏原有大结构的证据时，继续继承仍兼容且有效的 `author_exact_state`；否则显示 `base_state`。若真实结构证据使 `base_state` 离开 `author_exact_base_state`，只将 `author_exact_active` 机械设为 `false`，保留作者原话、日期、父状态和来源。以后基础状态返回旧父状态也不自动激活，必须由较新作者明确重申。

固定24行每天全部出现且顺序不变。涨3/跌3去重集合中的其他行业只有存在可靠代表ETF时才追加在固定24行之后；大数据、金属商品、生物识别等没有可靠代表ETF的Theme或细分行业不得进入本节，但仍保留Finviz机械统计，并在第二、第三部分按既有规则处理重要方向。允许追加的行业若ledger没有状态，在后台检查已经整理好的近期价格结构，从五种合法 `base_state` 中补建；AI不得为新项目类比或复制其他项目的作者特殊阶段。

正式表格按 `板块/ETF｜当天表现｜行情性质及说明` 写出；兼容且有效的 `author_exact_state` 优先原样显示，否则显示 `base_state`。具体ETF状态先读取唯一 ledger 中的 `etf_states.states`，一次性外部ETF参考池不再读取。不得出现“初始性质”“新增”“建档”“作者历史”“ledger”“强制覆盖”等后台话术。
