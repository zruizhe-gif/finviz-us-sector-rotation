# 03 Current Overrides and Precedence｜当前稳定覆盖规则

本文件只保存对原日度、周度任务合同的长期稳定覆盖项。具体日期、具体板块行情判断、作者某次术语修正和最新报告日期全部属于state，不得写入本文件。

运行模式、增量同步、缓存与AI报告路径统一以 `14-runtime-modes-and-incremental-workflow.md` 为准。

## 目录

1. 规则优先级
2. Finviz机械统计保持完整
3. Finviz主统计报告
4. 独立轮动报告固定结构
5. 作者术语与成稿边界

## 规则优先级

1. 用户当前请求中的明确要求；
2. `14-runtime-modes-and-incremental-workflow.md`；
3. 本文件；
4. `01-original-daily-task-verbatim.txt` 与 `02-original-weekly-task-verbatim.txt`；
5. 其他辅助reference与模板。

原任务继续作为机械统计合同保存，但正常日度、周度运行不再全文重读。稳定程序生成的 calculated statistics、coverage audit、完整代码集合及其他大型JSON是机器计算与追溯底稿；LLM日常成稿的执行载体是由 `scripts/build_runtime_briefs.py` 生成的 `runtime-brief.json` 与 `catalyst-brief.json`。

## A. Finviz机械统计保持完整

以下范围和产物一项不减：

- All Stocks、S&P 500、Dow Jones 30、Nasdaq 100、Russell 2000；
- Themes；
- ETFs；
- 每个范围的涨3与跌3；
- 板块、主题宽度与准确收益；
- 个股去重集合；
- 纯个股TXT与全代码TXT；
- coverage audit和完整性审计。

### 一致性优先

- 五个股票范围先按全部有效成分判断板块方向；
- Themes先按全部有效子主题判断大类方向；
- 清一色上涨或下跌候选优先于平均表现；
- 只有清一色候选不足3项时，才按既定整体表现补位；
- 不能用三只极端股票代替全部成分统计；
- 每个入选项保留宽度、收益率和“清一色优先/平均表现补位”身份；
- 最终复核证明平均值没有越过一致性优先级。

### ETF

- 排除杠杆、反向和单股杠杆产品；
- 按底层经济敞口去重，而不只按代码或名称去重；
- 每个方向最终保留三个独立敞口；
- 保留法律形式、准确表现、主要驱动和被合并的相似敞口证据。

### 稳定代码边界

DAILY_WEEKLY_RUN只运行现有稳定抓取、计算和输出程序。模型不得为“再次确认”手工遍历全部股票，也不得修改 `fetch_and_build.py`、`calculate.py` 或 `generate_outputs.py`。程序真实报错时停止并报告；代码维护必须另行进入DEVELOPMENT。

完整底稿一项不删且永久保留。正常成稿禁止全文读取calculated、coverage、hierarchy/perf、ETF audit或完整catalyst cache；两个brief的质量门失败或出现具名异常时，才定点回查对应原始记录。该读取隔离不得改变统计范围、涨3跌3、个股覆盖或证据标准。

## B. Finviz主统计报告

主统计报告保持简洁、完整、可核验：

- 五个股票范围各使用一张恰好六行的四列表格；
- Themes使用一张恰好六行的四列表格；
- ETF分最终上涨三只和最终下跌三只；
- 结尾保留一致性优先复核与TXT代码审计；
- 每只入选股票的公司名称、代码、涨跌幅、证据级别和原因直接写在对应表格行内；
- 主统计报告保留可点击核验来源和发布日期。

五个股票范围的固定列为：`方向`、`板块与入选身份`、`宽度与整体收益`、`入选个股及原因`。

Themes固定列为：`方向`、`主题与入选身份`、`子主题宽度与等权收益`、`主要子主题及个股原因`。

逐股催化研究按ticker去重缓存和有限升级机制执行，见 `14-runtime-modes-and-incremental-workflow.md` 与 `16-runtime-briefs-and-batch-catalysts.md`。全部ticker先由同一批量机械筛查覆盖；同一ticker不得因跨范围或跨主题出现而重复研究。

## C. 独立轮动报告固定结构

日度固定六部分：

1. 核心结论；
2. 当天板块轮动情况；
3. 驱动因素、盈利预期和持续性；
4. 行情性质；
5. 商品涨跌驱动判断；
6. 未来观察点。

周度仅将第二部分改为“本周板块轮动情况”，其余标题不变。原“最终结论与持续性”章节废止，不做重复总结或持续性排行榜。

日度标题固定写成 `美股板块轮动观察｜YYYY.M.D`，月份和日期不补0。Markdown成稿的标题与六部分标题全部使用普通正文加粗，不使用 `#`、`##`、`###` Heading语法。未来日度AI候选文件固定为 `AI_reports/daily/美股板块轮动观察｜YYYY.M.D.md`；不追溯重命名旧报告。

### 核心结论

只能写一个高信息密度段落，在一段内说明宏观环境、是否存在真实热点、最重要轮入和轮出、风格变化、真假板块信号及最重要的行情性质变化或维持。不得拆成多段复述后文。

### 第二部分：三项轮入与三项轮出

Finviz机械统计完成后，在后台建立 `MANDATORY_ROTATION_COVERAGE_SET`：包括五个股票范围各自涨3、跌3及Themes涨3、跌3；跨范围同名项目去重，但保留各范围证据。

第二部分另建 `SELECTED_ROTATION_3_IN_3_OUT`：

1. 统计方向在六个范围进入涨3或跌3的频率；
2. 名称相近、底层成分高度交叉且经济敞口实质相同的方向先合并；共享一个宏观叙事不足以合并；
3. 按频率、独立范围数、宽度、代表ETF、权重股、准确相对收益与可得真实流量复核；
4. 严格选出三项轮入与三项轮出。

表格必须恰好六行、严格四列：

| 轮动强度 | 板块和主题 | 当日表现情况 | 轮动分析 |
|---|---|---|---|
| 轮入1 |  |  |  |
| 轮入2 |  |  |  |
| 轮入3 |  |  |  |
| 轮出1 |  |  |  |
| 轮出2 |  |  |  |
| 轮出3 |  |  |  |

周报第三列改为“本周表现情况”，其余列名不变。不得增加第五列，不得把内部覆盖来源写入正文。

### 第三部分：只分析最终六项

- 只分析第二部分最终选出的三项轮入和三项轮出；
- 每个不同板块或主题单独设小标题；
- 只有底层成分和经济敞口实质相同的方向可以合并；
- 每项依次说明直接触发、产业与宏观背景、盈利预期；
- 只有基础行情性质为上涨趋势或下跌趋势时，才写趋势维持和破坏条件；
- 大型震荡、头部、底部不写持续性或持续条件。

### 第四部分：基础状态与作者精确阶段

AI能够自主创建的 `base_state` 只有：

- 上涨趋势；
- 下跌趋势；
- 大型震荡；
- 头部；
- 底部。

作者正式报告明确给出的更具体阶段保存在 `author_exact_state`，不是第六种AI基础分类。创建时记录其五类父状态 `author_exact_base_state`、作者来源 `author_exact_source_report`，并将 `author_exact_active` 设为 `true`。只有 active 为 true 且当前 `base_state` 仍等于该父状态时，报告才原样继承作者用词；否则显示 `base_state`。基础状态离开父状态时只把旧精确阶段转为 inactive 历史记录，不删除；基础状态以后返回也不得自动复活，须由较新作者判断重新激活。AI不得给其他板块创造同类精确阶段。

第四部分严格执行 `references/15-fixed-section-four-etf-pool.md`：先按固定顺序完整写24行，使用三列 `板块/ETF｜当天表现｜行情性质及说明`；双ETF行同时取得两只ETF表现，能源和金融各合并为一行。当天涨3/跌3中的其他行业只有存在可靠代表ETF时才追加在24行之后；无可靠代表ETF的Theme或细分行业不得进入第四部分。VGT等已列入禁用关系的重复ETF不得单列。该限制只改变第四部分展示池，不删减Finviz机械统计、mandatory coverage、第二部分选取或第三部分分析。

正式正文只展示最终行情性质，不展示首次出现、建档、历史同步、ledger或来源优先级等内部过程。

### 商品

商品同样使用五类 `base_state`。上涨趋势和下跌趋势可以写趋势维持与破坏条件；大型震荡、头部、底部只写当期驱动、供需、盈利预期和内部结构，不写持续性评级。

## D. 作者术语与成稿边界

所有具体板块、主题、ETF和行业中文名称均从 `state/author-terminology.yaml` 读取。规则文件不保留一份具体映射副本，也不得根据当日成分表现临时重新命名。

正式轮动报告：

- 除公司法定名称、股票代码、ETF代码和必要指数/数据范围专名外，板块、行业、子行业、主题与子主题统一使用作者术语表中的中文名称；
- 公司名称必须同时附股票代码；
- 删除全部URL、超链接、引用标记、脚注、来源尾注和资料来源章节；
- 不得出现技术指标、投资或交易建议；
- 不得出现作者历史、state、ledger、同步、缓存、强制覆盖、审计、字幕路径或“节目提到”等生成过程话术。

## E. AI候选稿与作者正式历史

- AI日度候选稿只写入 `AI_reports/daily/`；
- AI周度候选稿只写入 `AI_reports/weekly/`；
- AI不得自动把候选稿复制、移动或覆盖到 `history/`；
- 只有作者人工修改或用户明确确认的报告才能成为 `AUTHOR_CONFIRMED_HISTORY`；
- 作者正式历史优先于AI候选稿、旧state和Codex此前判断；
- AI候选稿不得反向创建或覆盖作者精确状态和作者术语。

## F. 唯一最终审计

所有统计、连续性、Voice Style、Hard Bans、格式和出版清理合并到一次最终综合审计。通过后立即结束。若有失败项，只定点修正并定点复查，不得重新执行第二轮或第三轮全量审计。
